# 2.4 Validation suite: regression tests + acceptance criteria for every built feature

⚠️ **Medium**: about 25 new files across pytest, Playwright, a runner script and a report generator. Each piece is simple and independently checkable. Built in 3 waves of parallel `coder` agents.

## Context
The app now has Module 1 (auth, threads, streaming chat, Stop, tracing) and Module 2 (Chat Completions with self-managed history, ingestion with Realtime, the `search_documents` retrieval tool). Every plan validated its own feature once, by hand, with curl, Playwright MCP and LangSmith. Nothing re-runs those checks, so a new feature can quietly break an old one.

Goal: **one command that re-validates every built feature** and writes a per-feature PASS/FAIL report, plus a `/validate` command so an agent can run it, triage failures and report. Each feature gets an ID and written acceptance criteria. Future plans add their own entries and tests.

User decisions:
- **Scripted suite plus an agent report.** pytest covers API, RLS and SSE; Playwright spec files cover the browser. The agent runs and triages; it does not hand-test.
- **Dedicated test users.** `rag-test-val-a@example.com` and `rag-test-val-b@example.com` (password `TestPass123!`). The suite wipes and re-seeds their data on every run, so manual testing on `rag-test-a/b` never interferes.

## Architecture

```
scripts/validate.sh [quick|full] [--only <regex>] [--restart]
  1. static   pytest unit (-m "not live"), tsc -b, lint vs baseline, repo-rule tests, (full: npm run build)
  2. services reuse if :8000 and :5173 are healthy, else start-services.sh (stopped again at exit); --restart forces fresh
  3. api      pytest -m live            (quick: -m "live and not llm")
  4. e2e      npx playwright test        (quick: --grep @smoke)
  5. traces   python -m app.scripts.check_traces   (full only; SKIP if tracing is off)
  6. report   python -m app.scripts.validation_report → validation-report/<ts>/report.md (+ latest symlink)
  exit code 0 only if no FAIL
/validate [quick|full|<ID regex>]  → agent runs it, reads report.md, triages each FAIL, reports, shuts down
```

**Test ↔ feature mapping:** every test carries its catalogue ID in its name.
- pytest: `test_AUTH_02_me_requires_token`
- Playwright: `test('AUTH-03 sign in with valid and invalid credentials @smoke', …)`

The report generator extracts IDs with the regex `\b([A-Z]{2,4})[-_](\d{2})\b`, joins the results against `validation/FEATURES.md`, and flags catalogue IDs that have no test (`UNCOVERED`) and tests whose ID isn't in the catalogue (`UNKNOWN`).

**LLM nondeterminism policy:**
- Protocol, data and security assertions are hard.
- Model-behaviour assertions (memory recall, "searches for doc questions", "no search for small talk", fact in answer) are marked `llm` and get **one retry in a fresh thread** via a helper. Playwright uses `retries: 1`.
- A pass on retry is reported as `PASS (flaky)`, so instability stays visible without failing the run.
- Questions use facts that retrieve well (similarity ≥ 0.4). Don't use the borderline call-sign question.

**Fault injection without restarts:** failure paths (LLM down, embedding down) run **in-process** through `httpx.ASGITransport(app=app)` against the real Supabase, with `monkeypatch` on the failing dependency. UI error states use Playwright `page.route` mocks. Neither needs `.env` edits or a service restart.

## Verification (end to end)
1. With no services running, `scripts/validate.sh quick` starts the services, everything is PASS/SKIP/NOT RUN, and it exits 0. Afterwards `lsof -iTCP:8000 -iTCP:5173 -sTCP:LISTEN` is empty (it stopped what it started).
2. `scripts/validate.sh full` gives all 49 IDs PASS or PASS (flaky), OBS-01/02 PASS, and a runtime of about 10 min or less.
3. **The suite catches breakage.** Use env overrides only, with no code edits, and run `--restart` each time:
   - `RETRIEVAL_MIN_SIMILARITY=0.99 scripts/validate.sh full --restart --only RET` → RET-02 and RET-08 FAIL.
   - `LLM_MODEL=nonexistent/model scripts/validate.sh full --restart --only CHAT` → CHAT-01/02/03 FAIL with the provider error as evidence.
   - Then a plain `--restart` run is green again.
4. Run `/validate quick` as an agent. It produces the summary table and confirms shutdown.
5. Your manual accounts `rag-test-a`/`rag-test-b` are untouched: their document lists before and after a full run are the same.
