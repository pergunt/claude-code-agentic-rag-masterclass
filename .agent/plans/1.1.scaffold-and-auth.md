# 1.1 Scaffold + Auth

⚠️ **Medium**: many files and tooling setup (Tailwind/shadcn versions), but low logical risk. Single-pass feasible.

Parent: `1.module-1-overview.md`

## Tasks

1. **Backend scaffold**
   - `python3 -m venv backend/venv`.
   - `requirements.txt`: `fastapi`, `uvicorn[standard]`, `pydantic-settings`, `supabase`, `openai`, `langsmith`, `python-dotenv`.
   - `main.py`: CORS for `FRONTEND_ORIGIN` and `GET /health`.
   - Settings default to empty strings so the app boots without keys.
   - *Validate:* `uvicorn app.main:app --reload`, then `curl localhost:8000/health` returns `{"status":"ok"}`.

2. **Frontend scaffold**
   - `npm create vite@latest frontend -- --template react-ts`.
   - Tailwind, `shadcn init`, and the components `button input textarea card scroll-area separator`.
   - react-router with `/login` and `/` routes.
   - *Validate:* `npm run build` passes; `npm run dev` serves the page.

3. **Schema migration** `supabase/migrations/0001_threads_messages.sql`
   - `threads(id uuid pk default gen_random_uuid(), user_id uuid not null default auth.uid() references auth.users on delete cascade, title text not null default 'New chat', openai_conversation_id text, created_at, updated_at)`
   - `messages(id uuid pk, thread_id uuid references threads on delete cascade, user_id uuid not null default auth.uid() references auth.users, role text check (role in ('user','assistant')), content text not null, created_at)`
   - Enable RLS on both tables, with select/insert/update/delete policies `using (user_id = auth.uid())` / `with check (user_id = auth.uid())`.
   - Indexes on `messages(thread_id, created_at)` and `threads(user_id, updated_at desc)`.
   - *Validate:* apply it in the SQL editor. `select tablename, rowsecurity from pg_tables where schemaname='public'` shows `true` for both tables, and a `select` as anon (no JWT) returns 0 rows.

4. **Backend auth**
   - `get_current_user` reads `Authorization: Bearer <jwt>`, verifies it via `supabase.auth.get_user(jwt)` and returns 401 on failure.
   - `db.py` builds a client with the anon key and `postgrest.auth(jwt)`, so every query runs under RLS. No service-role key in request paths.
   - Add `GET /api/me`.
   - *Validate:* `curl /api/me` without a token returns 401; with a valid token (from the frontend session) it returns the user id and email.

5. **Frontend auth**
   - `AuthProvider`: Supabase session + `onAuthStateChange`.
   - `LoginPage`: email/password sign-in and sign-up.
   - Protected route that redirects to `/login`, plus a sign-out button.
   - `api.ts` attaches `session.access_token`.
   - *Validate (browser via Chrome MCP):* sign up and land on `/`; a refresh keeps the session; sign-out returns to `/login`; the `/api/me` call succeeds in the network tab.
