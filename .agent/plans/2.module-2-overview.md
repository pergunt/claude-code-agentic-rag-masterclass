# Module 2: BYO Retrieval + Memory (overview)

🔴 **Complex**: split into three sub-plans, each ⚠️ Medium and single-pass feasible on its own. Build them in order, validating and committing each before the next.

## Decisions (made by the user, 2026-10-28)
- **Option A: Replace.** The Responses API code and the `threads.openai_conversation_id` column are removed entirely. Chat moves to the Chat Completions API against an OpenAI-compatible endpoint (default OpenRouter).
- **Embeddings: OpenAI `text-embedding-3-small`, 1536 dims**, via the existing `OPENAI_API_KEY`. Chat uses `LLM_API_KEY` (OpenRouter), and embeddings stay on OpenAI.

## Shared contracts (all three plans agree on these)
- **Migration numbers:** 0002 (2.1), 0003 (2.2), 0004 + optional 0005 (2.3).
- **Tables:** `public.documents(id, user_id, filename, storage_path, mime_type, size_bytes, status pending|processing|completed|failed, error, chunk_count, created_at, updated_at)` and `public.chunks(id, document_id → documents on delete cascade, user_id, chunk_index, content, embedding extensions.vector(1536), created_at)`. pgvector is in schema `extensions`.
- **Embeddings:** `app/services/embeddings.py` with sync `embed_texts(list[str]) -> list[list[float]]` and sync `embed_query(str) -> list[float]`.
- **Chat service:** `app/services/llm.py`, with `get_chat_client()`, `build_messages(history)`, `stream_completion(messages, tools)` (one streamed call ending in an internal `completion` event) and `@traceable chat_turn stream_reply(history, ctx=None)`. 2.3 turns `stream_reply` into the bounded tool loop.
- **SSE events:** `delta` / `tool {name, status, query?, sources?}` / `done {text, sources?}` / `error {message}`. The frontend's "Searching documents…" indicator is kept through 2.1 for 2.3.
- **History:** only `role`/`content` of `user`/`assistant` rows are ever sent to the model. Tool calls and results are never persisted.
- **Supabase clients:** request handlers use the user's JWT (PostgREST **and** Storage, after 2.2's `ClientOptions` fix). The service role is used only by background ingestion in `app/services/ingestion.py`.

## Secrets rule (all sub-plans)
`.claude/settings.json` denies reading or editing `.env` files. Agents never read, print, source or edit `backend/.env` or `frontend/.env`:
- **Test tokens:** curl tests get public config and test-user tokens from `eval "$(cd backend && venv/bin/python -m app.scripts.dev_tokens)"` (built in 2.1 Task 0).
- **Key presence:** checked via `get_settings()` and printed as `bool(...)` only.
- **One-off test settings:** passed as env overrides on the command, for example `INGESTION_STAGE_DELAY_SECONDS=3 ./scripts/restart-services.sh`.
- **`.env.example`:** read and edited with the Read/Edit tools. Bash `cat`/`grep` on paths containing `.env` is denied.
