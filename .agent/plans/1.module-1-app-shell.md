# Module 1 Planning: App Shell + Observability

## Context
The repo is greenfield (only PRD/README/CLAUDE.md/PROGRESS.md, empty `.agent/plans/`). Module 1 builds the app shell: Supabase auth, a threaded chat UI, chat powered by OpenAI's **Responses API** (managed conversation state + built-in `file_search`), streamed over SSE, with LangSmith tracing from day one. This is deliberately "managed RAG" — OpenAI holds memory and retrieval — so Module 2 can contrast it with BYO retrieval.

Decisions made with the user:
- **Supabase:** hosted project; user supplies URL/keys in `.env`; schema as SQL migration files applied via SQL editor (or `supabase db push`).
- **file_search docs:** user creates an OpenAI vector store in the dashboard, uploads a few files, sets `OPENAI_VECTOR_STORE_ID`. No upload UI in Module 1.
- **Thread state:** OpenAI **Conversations API** — Supabase `threads` row stores `openai_conversation_id`; a `messages` table mirrors messages for fast UI rendering.
- **Split:** one overview + 3 sub-plans, each built and validated separately (Module 1 overall is 🔴 Complex).

## Sub-plan 1.1 — Scaffold + Auth (⚠️ Medium)

1. **Backend scaffold**: `python3 -m venv backend/venv`; requirements: `fastapi`, `uvicorn[standard]`, `pydantic-settings`, `supabase`, `openai`, `langsmith`, `python-dotenv`. `main.py` with CORS for `FRONTEND_ORIGIN` and `GET /health`.
   - *Validate:* `uvicorn app.main:app --reload` → `curl localhost:8000/health` returns `{"status":"ok"}`.
2. **Frontend scaffold**: `npm create vite@latest frontend -- --template react-ts`, Tailwind, shadcn init, add `button input textarea card scroll-area separator`; react-router with `/login` and `/` routes.
   - *Validate:* `npm run build` passes; `npm run dev` shows placeholder page.
3. **Schema migration** `0001_threads_messages.sql`:
   - `threads(id uuid pk default gen_random_uuid(), user_id uuid not null default auth.uid() references auth.users on delete cascade, title text not null default 'New chat', openai_conversation_id text, created_at, updated_at)`
   - `messages(id uuid pk, thread_id uuid references threads on delete cascade, user_id uuid not null default auth.uid() references auth.users, role text check (role in ('user','assistant')), content text not null, created_at)`
   - Enable RLS on both; select/insert/update/delete policies `using (user_id = auth.uid())` / `with check (user_id = auth.uid())`; index on `messages(thread_id, created_at)`, `threads(user_id, updated_at desc)`.
   - *Validate:* apply in SQL editor; query `pg_tables` shows `rowsecurity = true` for both; as anon (no JWT) `select` returns 0 rows.
4. **Backend auth**: `get_current_user` reads `Authorization: Bearer <jwt>`, verifies via `supabase.auth.get_user(jwt)` → 401 on failure. `db.py` builds a client with anon key and `postgrest.auth(jwt)` so every query runs under RLS (no service-role key in request paths). Add `GET /api/me`.
   - *Validate:* `curl /api/me` without token → 401; with a valid token (from frontend session) → user id/email.
5. **Frontend auth**: `AuthProvider` (Supabase session + `onAuthStateChange`), `LoginPage` with email/password sign-in & sign-up, protected route redirecting to `/login`, sign-out button. `api.ts` attaches `session.access_token`.
   - *Validate (browser via Chrome MCP):* sign up, land on `/`, refresh keeps session, sign out returns to `/login`; `/api/me` call succeeds in network tab.

## Sub-plan 1.2 — Chat via Responses API + SSE (⚠️ Medium)

1. **Pydantic schemas**: `ThreadOut`, `ThreadCreate`, `ThreadUpdate`, `MessageOut`, `ChatRequest{content: str}`.
2. **Threads router**: `GET /api/threads` (by `updated_at desc`), `POST /api/threads` (calls `client.conversations.create()`, stores id), `PATCH /api/threads/{id}` (rename), `DELETE /api/threads/{id}` (delete row; best-effort `conversations.delete`), `GET /api/threads/{id}/messages`.
   - *Validate:* curl create → list → rename → delete with a user token; second user's token gets 404/empty for the first user's thread (RLS).
3. **LLM service** `services/llm.py`: `stream_reply(conversation_id, text)` calling
   `client.responses.create(model=OPENAI_MODEL, conversation=conversation_id, input=text, tools=[{"type":"file_search","vector_store_ids":[OPENAI_VECTOR_STORE_ID]}], stream=True)`; yields normalized events: `delta` (from `response.output_text.delta`), `tool` (from `response.file_search_call.*` → searching/completed), `done` (with full text), `error`.
   - *Validate:* small script `python -m app.scripts.smoke_chat "question about doc"` prints streamed text and a file_search event.
4. **Chat endpoint** `POST /api/threads/{id}/messages` → `StreamingResponse(media_type="text/event-stream")`: insert user message, stream `data: {json}\n\n` events, on completion insert assistant message and bump `threads.updated_at`; if thread title is default, set title to first 60 chars of the first user message. Errors emitted as an `error` event, not a broken stream.
   - *Validate:* `curl -N -H "Authorization: Bearer …" -d '{"content":"hi"}' …/messages` shows incremental `delta` lines then `done`; messages table has both rows.
5. **Chat UI**: `ChatPage` = `ThreadSidebar` (list, new chat, rename/delete) + `MessageList` (markdown via `react-markdown`, auto-scroll) + `Composer` (Enter to send, Shift+Enter newline, disabled while streaming). `api.ts` `streamMessage()` uses `fetch` + `ReadableStream` SSE parsing (EventSource can't send POST/auth header). Show "Searching documents…" indicator on `tool` events. Chat is the default view at `/`.
   - *Validate (browser via Chrome MCP):* new chat, ask doc-specific question, text streams progressively, answer references doc content; follow-up question uses prior context (proves Conversations memory); reload restores thread and messages; delete removes it.

## Sub-plan 1.3 — LangSmith tracing (✅ Simple)

1. Wrap the OpenAI client in `services/llm.py` with `langsmith.wrappers.wrap_openai(OpenAI())`; decorate `stream_reply` with `@traceable(name="chat_turn", run_type="chain")`, passing `metadata={"thread_id", "user_id"}` (no message content beyond what OpenAI wrapper logs).
2. Config: `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT=agentic-rag-masterclass`; tracing is a no-op when unset.
3. If `wrap_openai` doesn't capture streamed Responses output in the installed version, fall back to manually logging the final text in the `traceable` outputs.
   - *Validate:* send a chat message → LangSmith project shows a `chat_turn` run with the nested OpenAI call, input, streamed output, and thread/user metadata; with `LANGSMITH_TRACING` unset the app still works.
