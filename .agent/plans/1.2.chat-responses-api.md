# 1.2 Chat via Responses API + SSE

⚠️ **Medium**: streaming event shapes from the Responses API may need iteration. Depends on 1.1.

Parent: `1.module-1-overview.md`

## Tasks

1. **Pydantic schemas**: `ThreadOut`, `ThreadCreate`, `ThreadUpdate`, `MessageOut`, `ChatRequest{content: str}`.
   - *Validate:* `python -c "import app.schemas"` succeeds.

2. **Threads router**
   - `GET /api/threads`, ordered by `updated_at desc`.
   - `POST /api/threads`: calls `client.conversations.create()` and stores the conversation id.
   - `PATCH /api/threads/{id}`: rename.
   - `DELETE /api/threads/{id}`: deletes the row, with a best-effort `conversations.delete`.
   - `GET /api/threads/{id}/messages`.
   - *Validate:* with a user token, curl create → list → rename → delete. A second user's token gets 404 or an empty result for the first user's thread (RLS).

3. **LLM service** `services/llm.py`
   - `stream_reply(conversation_id, text)` calls `client.responses.create(model=OPENAI_MODEL, conversation=conversation_id, input=text, tools=[{"type":"file_search","vector_store_ids":[OPENAI_VECTOR_STORE_ID]}], stream=True)`. The tool is omitted when no vector store is configured.
   - It yields normalized events:
     - `delta`, from `response.output_text.delta`
     - `tool`, from `response.file_search_call.*` (searching/completed)
     - `done`, with the full text
     - `error`
   - *Validate:* `python -m app.scripts.smoke_chat "question about doc"` prints the streamed text and a file_search event.

4. **Chat endpoint** `POST /api/threads/{id}/messages` → `StreamingResponse(media_type="text/event-stream")`
   - Insert the user message, then stream `data: {json}\n\n` events.
   - On completion, insert the assistant message and bump `threads.updated_at`.
   - If the thread title is still the default, set it to the first 60 chars of the first user message.
   - Errors are emitted as an `error` event, not a broken stream.
   - *Validate:* `curl -N -H "Authorization: Bearer …" -d '{"content":"hi"}' …/messages` shows incremental `delta` lines and then `done`; the messages table has both rows.

5. **Chat UI**
   - `ChatPage` = `ThreadSidebar` (list, new chat, rename/delete) + `MessageList` (markdown via `react-markdown`, auto-scroll) + `Composer` (Enter sends, Shift+Enter adds a newline, disabled while streaming).
   - `api.ts` `streamMessage()` parses SSE with `fetch` + `ReadableStream`, because EventSource can't send a POST or an auth header.
   - Show a "Searching documents…" indicator on `tool` events.
   - Chat is the default view at `/`.
   - *Validate (browser via Chrome MCP):*
     - Start a new chat and ask a doc-specific question. The text streams progressively and the answer references doc content.
     - A follow-up question uses the prior context, which proves Conversations memory.
     - A reload restores the thread and its messages.
     - Delete removes the thread.
