# 1.4 Stop streaming + quiet background load errors

⚠️ **Medium** - small surface (4 frontend files, 2 backend files + smoke script), but the backend
cancellation path needs care. Single-pass feasible.

## Goal
1. While an assistant reply is streaming, the Send button becomes a red Stop button. Clicking it
   stops the reply: the client aborts the request, the backend cancels the OpenAI stream, and the
   text streamed so far is kept on screen and saved as the assistant message.
2. Opening the app (or signing in) without doing anything never shows an error under the composer.
   A failure of the automatic thread-list load is logged to the console only. A failure the user
   triggers (send, rename, delete, opening a thread) still shows an error, and network failures read
   "Can't reach the server…" instead of the browser's raw "Failed to fetch".

## Why the backend changes
`chat_events` is a sync generator. Starlette runs it in a threadpool and, on client disconnect,
cancels the async side but never explicitly closes the sync generator. So the OpenAI stream keeps
running until garbage collection, and the assistant message is only saved on `done` (the known
"not saved on disconnect" follow-up). Making the streaming path async lets cancellation propagate.

## Tasks

### 1. `backend/app/services/llm.py`: async streaming
- Add `get_async_client()` (`wrap_openai(AsyncOpenAI(...))`, `lru_cache`). Keep the sync client for
  `create_conversation` / `delete_conversation` (used by sync thread endpoints).
- `stream_reply` becomes an async generator (same events, still `@traceable`), iterating the
  response inside `async with stream:` so cancellation closes the OpenAI HTTP stream.
- `app/scripts/smoke_chat.py`: drive it with `asyncio.run`.
- *Validate:* `venv/bin/python -m app.scripts.smoke_chat "…doc question…"` still prints deltas,
  file_search events and `[done]`.

### 2. `backend/app/routers/chat.py`: save partial reply on disconnect
- `chat_events` becomes an async generator. Collect deltas; on `done`, save the full reply
  (sync supabase calls via `run_in_threadpool`). In `finally`, if the stream ended without `done`
  or `error` (client disconnected), save the partial text inside `anyio.CancelScope(shield=True)`
  so the save survives the cancellation. Saving also bumps `updated_at` and sets the default title.
- *Validate:* curl the SSE endpoint with `--max-time 3` on a long question, then list messages:
  the assistant row holds a partial reply; the backend log shows no traceback.

### 3. `frontend/src/lib/api.ts`: readable network errors
- Wrap `fetch`: a `TypeError` (network failure) becomes `ApiError(0, "Can't reach the server…")`.
  An `AbortError` is rethrown untouched.
- *Validate:* with the backend stopped, sending a message shows the new message.

### 4. `ChatPage.tsx` + `Composer.tsx`: Stop button, quiet initial load
- `ChatPage`: an `AbortController` per send (ref), passed to `streamMessage`; `handleStop` aborts it;
  abort on unmount. An `AbortError` is not an error: keep the partial assistant text, drop an empty
  bubble, refresh threads.
- `refreshThreads` (automatic background load) logs failures with `console.warn` instead of setting
  the composer error.
- `Composer`: new `streaming` / `onStop` props. While streaming, render a solid red Stop button
  (`Square` icon, `bg-destructive text-white`, `aria-label="Stop"`, `type="button"`) in place of Send.
- *Validate (browser):* ask a long question, see the red Stop button, click it mid-stream: streaming
  halts, partial text stays, Send returns; reload: the partial reply is still there; a follow-up
  question works in the same thread; a new chat's first message streams normally.
  With the backend stopped: sign in, no error shown; send: "Can't reach the server…".

### 5. Wrap-up
- `npx tsc -b`, `npm run lint` (no new warnings), update PROGRESS.md, shut down all services.
