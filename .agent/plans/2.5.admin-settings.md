# 2.5 Account menu, admin role and global LLM/embedding settings

🔴 **Complex overall**, so it's split into three sub-plans, each ⚠️ **Medium** and single-pass feasible, built in order: **2.5.1** admin role + account menu + app sidebar → **2.5.2** runtime settings backend (Vault, admin API) → **2.5.3** Settings modal UI + re-index. Each sub-plan ends with its own validation and validation-suite rows (CLAUDE.md "Validation suite").

Prerequisite: plan 2.4 (validation suite) is built and green. This plan adds catalogue rows and tests to it.

## Context
- Users want the ChatGPT-style account button bottom-left in the sidebar: initials, with a menu holding the email, **Settings** and **Sign out**.
- **Settings** opens a modal where an **admin** configures the app globally. It has exactly **two sections** (user spec, 2026-10-28):
  - **LLM configuration**: model name, base URL, API key.
  - **Embedding configuration**: model name, base URL, API key, dimensions (read-only, shows 1536).
  - API key fields are `type="password"` inputs, so their values are never visible.
  - Base URL and model name are plain text inputs (no provider presets, no `/models` picker).
  - Not in the modal (stay env-only): `CHAT_MAX_OUTPUT_TOKENS`, `RETRIEVAL_TOP_K`, `RETRIEVAL_MIN_SIMILARITY`, `AGENT_MAX_TOOL_ROUNDS`.
- Only users with `is_admin = true` see it or can use it.
- Today all of this lives in `backend/.env` (`config.py` `Settings`). Changing it means editing the file and restarting.

## Decisions (best practices applied)

**D1. Where `is_admin` lives: a `public.profiles` table, not `auth.users`.**
- `auth.users` is owned by Supabase Auth. Adding columns there is unsupported and can break on platform upgrades.
- The Supabase pattern is a `public.profiles` row per user (`id → auth.users.id`), created by a trigger on sign-up, with RLS:
  - users can **read** their own row
  - there are **no** insert/update/delete policies, so nobody can promote themselves through the API
- Admins are promoted in the SQL editor (`update public.profiles set is_admin = true where email = …`).
- Alternative considered: `app_metadata.role` in the JWT. It's also tamper-proof, but it needs a token refresh to take effect and is harder to query in SQL policies. `profiles` is simpler and visible.

**D2. Configuration is layered: an admin override in the DB beats `.env`, which beats the code default. Yes, keep `.env` as the fallback.**
This is standard 12-factor practice, not a bad one:
- `.env` is the **deployment default and bootstrap**. A fresh deploy, or a DB with no overrides, still works.
- It's also the recovery path: if an admin saves a broken key, "Reset to default" returns to `.env`.
- The DB holds **runtime overrides** made by admins without a restart. Each field is nullable: `null` means "use the default".
- The risk of layering is confusion about which value is active. So the API and the UI show the **source** of every field ("App setting" vs "Environment default") and the effective value.

**D3. Secrets: Supabase Vault, write-only from the browser.**
- API keys are stored in **Supabase Vault** (`vault.secrets`), which is encrypted at rest with keys Supabase manages. They never go in a plain table column.
- **Write path:** browser → backend admin API → `set_app_secret` RPC. That's `security definer`, checks `is_admin()`, and allows only the names `llm_api_key` and `embedding_api_key`.
- **Read path:** only the backend can decrypt, through the `get_app_secrets()` RPC, which is granted to `service_role` only. An admin's JWT can't read decrypted keys through PostgREST either.
- **The browser never receives a key.** The API returns `{configured, source, last4}` only. The key input is "replace" only.
- Keys are never logged, traced or included in errors. A provider error is relayed by its message, which doesn't contain the key.
- This needs a **second narrow service-role exception**, `app/services/app_settings.py` (read config and secrets). Update the CLAUDE.md rule and the STA-04 repo-rule test to allow exactly `ingestion.py` + `app_settings.py`.

**D4. Embedding changes are guarded.**
- `chunks.embedding` is `vector(1536)`, so the dimensions are fixed. The modal shows **Dimensions: 1536** read-only; it's never in the PUT body. The model name is free text (any OpenAI-compatible embedding endpoint), still called with `dimensions=1536`. A model that can't return 1536 dims fails **Test connection** and ingestion (the existing size assert), so the admin sees it before saving.
- The embedding base URL is new: env `EMBEDDING_BASE_URL` in `config.py` (default `https://api.openai.com/v1`, add to `.env.example`). The embedding key env stays `OPENAI_API_KEY`.
- Vectors from different models aren't comparable, so each document records the `embedding_model` it was embedded with.
- **Embedding lock (user decision, 2026-10-28; replaces the earlier re-index flow):** while **any chunks exist** (counted across all users with the service role in `app_settings.py`, since settings are global), the embedding **model name** and **base URL** can't change:
  - `PUT /api/admin/settings` returns **409** `"Embedding settings are locked: N chunks exist. Delete all documents to change the embedding model."` when a submitted `embedding_model` / `embedding_base_url` (a `null` resolves to the env default) differs from the current effective value. Re-saving the same value is allowed.
  - The embedding **API key** stays editable (key rotation doesn't change vectors).
  - The modal disables those two inputs (and their Reset action) with that hint.
  - There is no re-index button, endpoint or stale-documents count.

**D5. Base URLs and models.**
- Both base URLs (LLM and embedding) are plain text inputs. They must be `https://`, with `http://` allowed only for `localhost`/`127.0.0.1`. A trailing `/` is stripped.
- Model names are plain text inputs: non-empty, ≤ 200 chars, no whitespace. There are no presets and no `/models` lookup.
- **Test connection** runs on the submitted values: a 1-token chat completion with `tools` declared, plus embedding `"ping"` giving 1536 dims. Save is allowed after a failed test, but the modal warns.

**D6. Runtime config cache.**
- `get_runtime_config()` merges the DB over the env and caches for 30 s per process. Saving invalidates the local cache immediately.
- The chat and embedding clients are cached per `(base_url, api_key)` instead of the current single `lru_cache`.
- Multi-process deploys pick changes up within 30 s. Documented.

## Sub-plan 2.5.2: Runtime settings backend

### Tasks
1. **Migration `0007_app_settings.sql`:**
   - `public.app_settings` is a single row: `id boolean primary key default true check (id)`, with nullable overrides:
     - `llm_base_url text`, `llm_model text`
     - `embedding_base_url text`, `embedding_model text`
     - `updated_at timestamptz`, `updated_by uuid`
     - No dimensions column (fixed at 1536) and no retrieval/max-token columns (env-only).
   - Insert the one row. RLS: `select`/`update` using `public.is_admin()`; no insert or delete.
   - `public.documents` add `embedding_model text`, nullable; null means "unknown (pre-2.5)".
   - Vault:
     - `create extension if not exists supabase_vault`, which is preinstalled on hosted projects.
     - `public.set_app_secret(p_name text, p_value text)` (definer):
       - Raise unless `is_admin()`, and raise unless `p_name in ('llm_api_key','embedding_api_key')`.
       - An empty or null value deletes the vault secret named `app:<p_name>`. Otherwise it calls `vault.update_secret`, or `vault.create_secret` if it doesn't exist yet.
       - Grant to `authenticated`.
     - `public.app_secret_status()` (definer, raises unless admin): returns `name, updated_at, right(decrypted_secret, 4) as last4` for the two names. Grant to `authenticated`.
     - `public.get_app_secrets()` (definer): returns `name, decrypted_secret`. `revoke all … from public, anon, authenticated`; `grant execute … to service_role`.
   - Commented validation SQL at the end (as in 0004).
2. **`app/services/app_settings.py` (new; service-role exception D3):**
   - `@dataclass(frozen=True) RuntimeConfig`: `llm_base_url, llm_api_key, llm_model, embedding_base_url, embedding_api_key, embedding_model, embedding_dimensions` (always `get_settings().embedding_dimensions`, never overridden), plus `sources: dict[str, Literal["app","env"]]` for the six overridable fields. Retrieval knobs and `chat_max_output_tokens` stay on `get_settings()`.
   - `get_runtime_config() -> RuntimeConfig`: sync, with a 30 s TTL cache guarded by a `threading.Lock`. It reads `app_settings` + `get_app_secrets()` with `create_service_client()`.
   - If Supabase is unreachable or the service key is missing, it **logs and falls back to env**, and never breaks chat.
   - `invalidate()`.
3. **Switch the call sites** to the runtime config:
   - `llm.get_chat_client(base_url, api_key)`: cached per pair.
   - `stream_completion` takes `cfg` and uses `cfg.llm_model` and the OpenRouter check on `cfg.llm_base_url`; `max_tokens` still comes from `get_settings().chat_max_output_tokens`.
   - `stream_reply(history, ctx, cfg)` passes `cfg` through. Max rounds, top_k and min_similarity are unchanged (env via `get_settings()`).
   - `embeddings.get_client(base_url, api_key)` cached per pair (`OpenAI(base_url=…, api_key=…)`); `embed_texts`/`embed_query` read the base URL, model, key and dims from `get_runtime_config()`.
   - `ingestion.ingestion_configured()` checks the effective embedding key.
   - `process_document` stores `documents.embedding_model`.
   - `routers/chat.py` gets `cfg` once per request in the sync handler, passes it on, and puts `model: cfg.llm_model` in the LangSmith metadata.
   - Scripts (`smoke_chat`, `check_retrieval`) use the runtime config too.
4. **Admin API, `app/routers/admin.py`.** Every route depends on `require_admin` and uses the user-JWT client for writes, so RLS plus `is_admin()` enforce again in the DB:
   - `GET /api/admin/settings` → `AdminSettingsOut`. Each field is `{value, source, default}`; keys are `{configured, source, last4}`; plus `embedding_dimensions` (read-only), `chunk_count: int` (all users, service role in `app_settings.count_chunks()`) and `embedding_locked: bool` (`chunk_count > 0`).
   - `PUT /api/admin/settings`, body `AdminSettingsIn`. All fields are optional; **omitted means unchanged, `null` means reset to the env default**. Pydantic `model_fields_set` decides which. Validation:
     - Fields: `llm_base_url`, `llm_model`, `llm_api_key`, `embedding_base_url`, `embedding_model`, `embedding_api_key`. Any other field (e.g. `embedding_dimensions`) → 422 (`extra="forbid"`).
     - base URLs and model names per D5
     - keys 10–400 chars, no whitespace
     Secret writes go through `rpc("set_app_secret")`. Then `invalidate()`, and return the new GET body.
   - `POST /api/admin/settings/test`: the same body shape, layered over the effective config **without saving**. It returns `{chat: {ok, error?, model}, embeddings: {ok, error?, dimensions}}`. Provider errors are trimmed to 300 chars and keys are never echoed.
   - The embedding lock (D4) is checked in PUT before anything is written (409, nothing saved).
   - Register the router in `main.py`.
5. **Docs:**
   - `.env.example` header comment: "defaults; admins can override in Settings".
   - CLAUDE.md service-role rule → `ingestion.py` and `app_settings.py`.
   - Memory `llm-provider.md`: precedence and Vault.
6. **Validation suite:** update **STA-04** rule 3's allow-list. New rows:
   - **ADM-03** admin-only (live): val-a gets 403 on every `/api/admin/*` route; val-a REST `app_settings` → `[]`; val-a `rpc set_app_secret` → error; any JWT `rpc get_app_secrets` → `42501`.
   - **ADM-04** secrets never leave the server (live): after val-admin sets a dummy embedding key via PUT, GET shows `configured: true, source: app, last4` matching, and no response body contains the full key. Then reset to `null`, and the source is back to `env`.
   - **ADM-05** override + reset (live, llm): PUT `llm_model=<current effective value>` and `embedding_base_url=<current effective value>` → GET shows those values with source `app`; a RET-style chat as val-a still streams and cites. PUT `null` for both → back to the env values, source `env`. A PUT with `embedding_dimensions` → 422.
   - **ADM-06** bad model surfaces cleanly (live, llm): PUT `llm_model="nonexistent/model"` → a chat turn gives an `error` event, not a traceback. Reset → chat works.
   - **ADM-07** test connection (live): the effective config gives `ok: true` on both parts; a bogus `llm_api_key` in the body gives `chat.ok: false` with an error, and nothing is saved (GET unchanged).
   - **ADM-08** embedding lock (unit + live): `process_document` writes `embedding_model`. With the suite's seeded chunks, GET shows `embedding_locked: true` and `chunk_count > 0`; PUT `embedding_model="text-embedding-3-large"` → 409 and GET unchanged; PUT `embedding_base_url` to a different URL → 409; PUT both at their current values → 200; the embedding key stays writable (covered by ADM-04).
   - **Suite hygiene:** the admin tests restore every override to `null` in `finally`, and `validation_fixtures.setup()` also resets `app_settings` (as val-admin) at the start, so a crashed run never leaves the app misconfigured for real users.
- *Validate:* migration checks (SQL: anon/authenticated can't execute `get_app_secrets`; `profiles` has no update policy), `pytest -q`, `validate.sh full`.

## Sub-plan 2.5.3: Settings modal UI + re-index

### Tasks
1. Add shadcn `label` (`npx shadcn add label`; `input` already exists), and a `SettingsDialog` (`components/settings/`) with **two stacked sections** (no tabs), in this order:
   - **LLM configuration**:
     - Model name: text input.
     - Base URL: text input.
     - API key: `type="password"` input, always empty on open (the browser never has the key), placeholder `•••• 1a2b · App setting` / `•••• 1a2b · Environment default` / `Not set`. Typing a value replaces the key on Save; leaving it empty means unchanged. A **Clear** action sends `null` (back to env).
   - **Embedding configuration**:
     - Model name: text input.
     - Base URL: text input.
     - API key: same password pattern as the LLM key.
     - Dimensions: read-only/disabled input showing `1536`, with the hint "Fixed by the database schema".
     - When `embedding_locked`: model name and base URL inputs are disabled (no Reset action) with an info notice: "Model and base URL are locked: N chunks already exist." plus why (stored vectors came from the current model; another model's vectors can't be compared, so search would be wrong) and how to unlock (delete all documents, re-upload; the key stays editable). The API key stays editable.
   - Every field shows a source badge (`App` / `Default`) and a "Reset to default" action (→ `null`).
   - Footer: **Test connection** (shows the ✓ / ✗ results per part), **Save** (disabled until something changes, and warns if the last test failed; on success the dialog **closes automatically**, on error it stays open with the error — user request 2026-10-28), **Cancel**.
   - Unsaved-changes guard on close.
2. Wire it into `AccountMenu` → Settings, admins only. Non-admins never fetch `/api/admin/*`.
3. **Validation suite:**
   - **UI-03** (e2e): Settings is hidden for val-a. As val-admin the dialog shows the two sections "LLM configuration" and "Embedding configuration", with source badges. Both API key inputs have `type="password"` and an empty value; Dimensions is disabled and shows 1536. A key field never shows more than `•••• last4`. Afterwards everything is reset.
   - **UI-04** (e2e): Test connection shows ✓ for chat and embeddings with the effective config.

## Out of scope
- Per-user model or key choice (settings are global, as requested).
- Choosing an embedding dimension other than 1536 (that would need a schema migration and a full re-embed). The field is display-only.
- Admin overrides for max output tokens and retrieval knobs (Top-K, min similarity, max tool rounds): they stay env-only.
- Provider presets and a `/models` picker: base URL and model are plain text.
- An admin user-management UI (promote and demote stay in SQL).
- Settings history or audit log beyond `updated_at` / `updated_by`.
